🔌 Nota modo del sensor: el AJ-SR04M viene de fábrica en modo HC-SR04 (trigger/echo). Sus pines RX y TX actúan como TRIG y ECHO respectivamente — no se necesita soldar resistencia (pads R19) para este modo. No conectar GPIO5 (esa placa lo usa para el LED onboard) ni GPIO16 (ocupado por el relé).

2. Identificación del dispositivo y MQTT

Cada copia se identifica por el sufijo MAC del ESP32. El prefijo MQTT de cada dispositivo es tanque_riego-<últimos 6 dígitos del MAC>/ y la entidad device id expone ese identificador (ej. TR-7a4e7c). Así conviven muchas copias sin colisión de tópicos.

Ejemplo: si el device id es TR-7a4e7c, el prefijo de tópicos es tanque_riego-7a4e7c/.

4. Riego manual (ahora / detener)

Para un riego puntual (se apaga solo al pasar los minutos de duracion riego):

# Duración de riego manual (minutos)
mosquitto_pub -h mqtt.petraka.com.ar -u alejandro -P piteroski1984 \
  -t 'tanque_riego-7a4e7c/number/tanque_riego_config_duracion_riego_min/command' -m 15

# Iniciar riego ahora

5. Sincronizar fecha/hora manualmente

El ESP32 sincroniza la hora automáticamente por NTP. Si se desactualiza, podés corregirla publicando fecha y hora en el tópico datetime: 

# Formato ISO: YYYY-MM-DD HH:MM:SS
mosquitto_pub -h mqtt.petraka.com.ar -u alejandro -P piteroski1984 \
  -t 'tanque_riego-7a4e7c/datetime/tanque_riego_config_fecha_hora/command' \
  -m '2026-09-21 18:30:00'

También podés ajustarla desde la web del device (http://192.168.1.237) en la entidad config fecha hora, o desde Home Assistant.

6. Funcionamiento sin internet / WiFi

💡 El riego no depende de internet. El ESP32 ejecuta los ciclos de riego localmente; la red solo se usa para telemetría y control remoto.

Comportamiento y respaldo de hora:

  1. Mientras el equipo esté alimentado, sigue regando según el plan de la SITUACIÓN aunque se caiga el WiFi/internet (usa su reloj interno).
  2. Al reiniciarse en frío sin red (ej. corte de luz en el campo), restaura la última hora conocida guardada en flash (g_last_epoch) y riega igual, aunque los horarios queden levemente corridos hasta resincronizar NTP.
  3. Sin red, MQTT queda offline (sensores/hora congelados en el broker) pero el relay funciona localmente.
  4. Cuando vuelve la conexión, NTP corrige la hora (on_connect → component.update: reloj_sntp) y el device vuelve a publicar en tanque_riego-7a4e7c/.

🔽 Modo configuración sin red: si no encontrás tu WiFi, a los ~20s se levanta el AP Setup Tanque Riego (clave centenario123, IP 192.168.4.1) con el captive portal para configurar otra red.

7. Ejemplo con Node-RED / Node.js (MQTT.js)

const mqtt = require('mqtt');
const DEV = 'tanque_riego-7a4e7c'; // device id -> prefijo MAC
const client = mqtt.connect('mqtt://mqtt.petraka.com.ar', {
  username: 'alejandro', password: 'piteroski1984'
});

client.on('connect', () => {
  // Cambiar a SITUACION 2
  client.publish(`${DEV}/select/tanque_riego_config_plan_riego/command`, 'SITUACION 2');
  // Activar programador
  client.publish(`${DEV}/switch/tanque_riego_programador_activo/command`, 'ON');
  // Corregir hora
  client.publish(`${DEV}/datetime/tanque_riego_config_fecha_hora/command`, '2026-09-21 18:30:00');
});

client.on('message', (topic, payload) => {
  console.log(topic, '=', payload.toString());
});
client.subscribe(`${DEV}/#`);

9. Calibración del sensor de distancia

El AJ-SR04M en modo trigger/echo puede desfasarse. Se corrige con el factor de calibración ajustable en vivo por MQTT (se guarda en memoria): 

# Setear factor de calibración (ej. para 60 cm reales -> leer 60)
mosquitto_pub -h mqtt.petraka.com.ar -u alejandro -P piteroski1984 \
  -t 'tanque_riego-7a5dd4/number/tanque_riego_config_factor_calibracion/command' -m 1.10

# Leer el factor actual
mosquitto_sub -h mqtt.petraka.com.ar -u alejandro -P piteroski1984 \
  -t 'tanque_riego-7a5dd4/number/tanque_riego_config_factor_calibracion/state' -v

🎯 Cómo calibrar: poner un objeto a una distancia conocida (ej. 60 cm), leer el valor reportado en sensor/..._distancia_cm/state y setear factor = distancia_real / distancia_medida. Valor de fábrica: 1.10.

11. Flasheo del firmware

  1. Conectar CH341A: TX↔RX, RX↔TX, GND↔GND (fuente externa para el ESP32).
  2. Mantener BOOT, tocar EN, soltar BOOT (modo download).
  3. esptool.py --port /dev/ttyUSB0 --baud 115200 --before no_reset --after hard_reset write_flash 0x0 firmware.factory.bin
  4. Si el device está online, actualizar por OTA: docker exec esphome esphome upload --device 192.168.1.237 /config/tanque_riego.yaml
